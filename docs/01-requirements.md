# 需求与成功标准

## 用户与目标

用户是需要处理待发布素材的内容运营。输入素材 ID、渠道与时间要求；系统读取素材和规则，返回审核状态、风险、候选时段、待确认项与草稿保存结果。

目标是生成可解释、无冲突且可复现的排期草稿。只操作合成数据与本地数据库，不执行真实发布。

## 范围

- 单 Agent、自定义轻量 Runner、Python CLI。
- 单渠道 douyin，固定 30 分钟候选时段，UTC+08:00。
- 单次请求一个素材，跨请求共享排期数据库。
- 本地素材读取、规则检查、时段查询、草稿保存四个业务工具。
- 可配置的真实模型工具调用接口，以及显式离线替身。
- 结构化结果、JSONL Trace、可执行测试和实际示例。

不做界面、真实发布、实际视频审核、向量检索、多用户权限、生产级 Runtime 或多 Agent。

## 必验标准

| 场景 | 成功标准 |
| --- | --- |
| 正常排期 | 审核通过、无冲突，数据库有且只有预期草稿，输出回执与数据库一致 |
| 素材信息缺失 | 列出缺失项，不保存，不虚构元数据 |
| 规则风险 | 列出规则 ID 和风险原因，阻断素材不可保存 |
| 时段冲突 | 根据占用补查替代，硬性变更未确认前不保存 |
| 重复提交 | 同内容请求返回原草稿 ID，数据库不增加行 |
| 保存失败 | 提交前故障回滚，输出明确失败，不虚报成功 |

补充验证：明确确认后的替代时段、人工复核、读取失败恢复、输入字段缺失、调用上限、占用改变后的动作变化，以及并发竞争和非法授权。

## 模型决策标准

真实模型至少完成“选择动作 → 执行工具 → 观察结果 → 调整下一步或结束”的循环。须保存至少两条不同结果导致不同动作的真实模型记录。固定分支的离线替身不满足此标准。

当前已使用 DeepSeek Flash 进行真实模式验收，升级后 14/14 通过；真实 normal 与 hard_conflict 等路径有独立 Trace。Mock 结果仍只证明流程，不能替代真实模型证据。

## 业务边界

- 请求编号为幂等标识。已保存后更改请求内容须使用新编号。
- 硬性时段变更只接受用户输入中的精确确认；模型无自行确认接口。
- 灵活时段仅在用户给定的当日窗口内选择。
- 保存成功意味着本地草稿存在；没有“已发布”状态。
- 元数据审核结果只适用于当前合成规则。
- 幂等返回反映原保存时的审核，不承诺最新规则重新审核。

## 交付完成条件

离线版本：代码可直接运行、必验场景有实际输出与 Trace、边界测试通过、文档准确披露 Mock 范围。

最终笔试提交：在离线版本基础上完成真实模型评估，候选人复现并确认个人贡献和工时，提供可读 GitHub 仓库和最终 commit SHA。
